## Приоритетные находки

### 1. Высокий: неверный экземпляр повторяющегося события

`modules/planning/scripts/calendar_task_sync.py:58` сохраняет первое событие с данным ID; строка 79 выбирает его для связанной задачи. Дата конкретного повторения не учитывается. В `modules/calendar/skills/hub-calendar/SKILL.md` прямо указано, что повторения серии имеют один ID.

Воспроизведение на искусственных данных через существующие тестовые функции: задача связана с событием 22 сентября; вход содержит повторения 21 и 22 сентября. Результат — `calendar_moved` на 21 сентября, хотя правильное повторение присутствует. Инструкция day-plan применяет такие результаты автоматически.

Исправить выбор конкретного повторения. До надёжного определения экземпляра неоднозначные серии не должны давать автоматическое изменение задачи. Дополнительно проверять calendar_id: сейчас искусственное событие с тем же ID из другого календаря тоже даёт `calendar_moved`; реальная коллизия ID не устанавливалась.

### 2. Высокий: связь с другой задачей того же проекта

В `calendar_task_sync.py:70` несвязанная задача сопоставляется по времени и project_id, без проверки названия задачи. Воспроизведение: название задачи `T`, название события `work/demo/Completely different task`, время совпадает. Результат — `unlinked`, который day-plan предлагает применять автоматически.

Нужна однозначная идентификация задачи, проверка отсутствия конкурирующих задач и отказ от автоматической связи при неоднозначности. Одного совпадения проекта и времени недостаточно.

### 3. Средний: даты расписания проверяются только по форме

`modules/tasks/scripts/task_records.py:16` принимает `Запланировано: 2026-99-99 25:70-00:00`. Для Due используется проверка настоящей даты, для расписания и ссылки на событие такой проверки нет.

Нужно централизованно проверять дату, время и допустимый порядок начала и конца; ошибочное поле не должно незаметно превращаться в отсутствие расписания.

### 4. Средний: правила и подключение требуют согласования

- `modules/core/data/ai/architecture.md:47` отменяет подтверждения записи, но ниже остаются старые требования одобрять записи реестра и изменения архитектуры. Приоритет формально задан, однако агенту приходится каждый раз разрешать противоречие. README также обещает подтверждения перед записью.
- `hub-project-migrate` разрешает необязательную очистку только сразу после переноса. `docs/update.md` направляет туда уже подключённые проекты со старыми правилами. Для такого проекта описанный путь очистки недоступен.
- `hub-project-register` создаёт карточку и запись реестра, но не содержит проверки или создания минимальной памяти задач. Следующий `hub-environment-check` предполагает наличие current-task.md. Нужно отдельно обозначить «зарегистрирован» и «готов к работе» и добавить проверку готовности существующему процессу.
- Ресурсы `registered-project-entry.md` и `registered-project-architecture.md` существуют, но поиск по modules/scripts/tests не нашёл ссылок на их имена. Entry-шаблон предлагает возвращаться к standalone setup, тогда как текущая документация объявляет такой режим снятым с поддержки.

Это основания для локального рефакторинга: один актуальный набор правил подтверждения, единый минимальный договор о файлах проекта и последовательный процесс подключения/проверки. Новая система модулей для этого не требуется.

### 5. Средний: устаревшая проверка версии

Из 190 тестов в tests прошли 189. `tests/test_rules_split.py:26` требует текст `Version: 2.0`, тогда как архитектура имеет версию 2.1. Причина падения установлена по коду и выводу теста. Это устаревшая проверка, а не доказательство отказа архитектуры.

## Подключаемые проекты

Для подключения достаточно согласованного слоя памяти и правил: зарегистрированный путь, читаемые файлы задач, корректные ID/статусы/даты, контекст проекта и отсутствие конфликтующих общих инструкций. Новым проектам нужен корректный шаблон. Старым может требоваться адресная адаптация этих файлов.

Минимальный вариант: исправить сопоставление календаря, проверку расписаний и тест версии. Это меньше работы, но оставляет противоречия инструкций и неполный процесс подключения.
