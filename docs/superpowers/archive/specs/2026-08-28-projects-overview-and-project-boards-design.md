# Обзор проектов и отдельные канбан-доски — дизайн

Дата: 2026-08-28

## Цель

Заменить перегруженную общую `Tasks-Kanban.md` компактным обзором всех
зарегистрированных проектов. Из обзора пользователь открывает отдельную
канбан-доску нужного проекта.

## Пользовательский интерфейс

`Projects-Overview.md` содержит ровно три колонки:

1. `Проект` — отображаемое имя проекта со ссылкой на его доску;
2. `Архипроект` — человекочитаемое имя основной группы проекта;
3. `Текущая задача` — первая содержательная строка раздела `## Goal` из
   `ai/current-task.md` либо `—`, если активной задачи нет.

Строка создаётся для каждого зарегистрированного проекта, включая архивные.
Целевая ссылка имеет стабильный вид
`Projects/<project-id>/Kanban.md` внутри локального Obsidian-хранилища.

## Отдельные доски проектов

Для каждого зарегистрированного проекта генератор создаёт
`Projects/<project-id>/Kanban.md`. Доска содержит только задачи этого проекта:
текущую, открытые записи `future-tasks.md` и записи `paused-tasks.md`.
Существующее соответствие статусов колонкам сохраняется.

Общая `Tasks-Kanban.md` удаляется из генерируемого набора. Генератор,
манифест, установка наблюдателя и синхронизация больше не считают её рабочим
представлением. Старые ручные доски Obsidian не изменяются.

## Редактирование и проверка

Исходные файлы проекта остаются единственным источником истины. Ручная правка
отдельной доски не меняет их напрямую. Сканирование сравнивает доску с
манифестом и создаёт proposal с точными операциями и идентификаторами проекта
и задачи.

ИИ-агент проверяет предложение по существующим правилам: источник задачи,
идентификатор, допустимость изменения и отсутствие неоднозначности. Только
после отдельного подтверждения пользователя агент вносит изменение в
`current-task.md`, `future-tasks.md` или `paused-tasks.md`. Затем доски
перегенерируются из подтверждённых источников.

Неизвестная задача, чужой project ID, дублирующий идентификатор, повреждённый
манифест или неоднозначное изменение блокируют proposal без записи в проект.

## Архипроекты

Используется существующее поле `primary_archiproject`; новое поле группы не
создаётся. В схему `ai/archiprojects.md` добавляется явное поле `kind` со
значениями `group` и `goal`. Для `kind: group` обязательны только `id`, `name`,
`status` и `kind`; поля `target`, `unit` и `due` отсутствуют. Для `kind: goal`
сохраняется прежняя числовая схема. Это позволяет не записывать фиктивный
`target: 0` и не ломает будущие измеримые архипроекты.

Начальные группы:

- `hadassah` — `Хадасса`;
- `businka` — `Бусинка`;
- `dela` — `Дела`;
- `masha` — `Маша`.

Проекты с тегом `hadassah` получают `primary_archiproject: hadassah`, проект
`zdorove-businki` получает `businka`, остальные существующие проекты — `dela`.
У группы `masha` пока нет проектов. После начального заполнения группа хранится
явно в карточке проекта и больше не вычисляется из тегов.

Карточка проекта сохраняет существующий комплект полей. Для группировки
записываются `archiproject_contribution: none` и
`related_archiprojects: none`; обзор читает только `primary_archiproject`.

## Генерация и манифест

Один манифест перечисляет обзор и все отдельные доски, их SHA-256 и исходные
файлы. Набор публикуется одной транзакцией: при сбое старый согласованный набор
восстанавливается полностью. Удаление проекта из реестра удаляет только его
сгенерированную доску при следующей подтверждённой публикации.

Первый переход со старого набора требует явного подтверждения записи в
локальное хранилище. Во время перехода удаляется только сгенерированная
`Tasks-Kanban.md`; ручные файлы не затрагиваются.

## Проверка

Контрактные тесты должны подтвердить:

- в обзоре ровно три нужные колонки и по одной строке на проект;
- имя проекта ведёт на правильную отдельную доску;
- на доске нет задач других проектов;
- ручная правка создаёт proposal, а не меняет источник;
- невалидные и неоднозначные изменения блокируются;
- манифест охватывает весь генерируемый набор;
- транзакционный сбой не оставляет частично обновлённые файлы;
- старая `Tasks-Kanban.md` больше не генерируется;
- реестр архипроектов и явная принадлежность проектов проходят проверку.

После реализации запускаются профильные shell-тесты,
`bash scripts/check-consistency.sh`, `bash scripts/smoke-test.sh` и
`git diff --check`.

## Вне задачи

- изменение содержимого старых ручных досок Obsidian;
- создание проектов группы `Маша`;
- новые поля обзора, фильтры, сортировка и показатели количества задач;
- прямое изменение файлов проекта без proposal и подтверждения.
