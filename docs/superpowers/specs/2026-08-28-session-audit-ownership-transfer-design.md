# Перенос механизма самоаудита в архитектуру

## Цель

Сделать `ai-dev-architecture` единственным владельцем методики, журнала,
безопасного индекса metadata и сценария периодического самоаудита. Проект
`hub-session-audit` остаётся неизменяемым архивом исходной работы.

## Границы

- Переносится только механизм аудита: скрипт индекса, его тест, методика,
  журнал и актуальный индекс metadata.
- Транскрипты не копируются и их содержимое не читается при переносе.
- Накопленный снимок из 30 сессий переносится только как архивная справка;
  рабочей очередью служит актуальный индекс из 51 сессии.
- Автоматически обновляется только безопасный индекс: ID файла, размер и дата
  изменения. Запись результата аудита разрешена лишь после выбора пользователем
  точных ID в текущем запуске.
- Никакой вывод аудита сам не меняет задачи, правила, настройки или
  архитектуру.

## Структура

`knowledge/session-audit/` содержит три записи:

- `procedure.md` — методика девяти проверок и правила безопасного evidence;
- `checked-sessions.md` — журнал уже проверенных сессий;
- `session-inventory.md` — генерируемый индекс metadata.

`scripts/refresh-session-inventory.sh` создаёт индекс. По умолчанию он пишет
в новый путь в проекте архитектуры; переменные окружения позволяют подменить
папку транскриптов, место вывода и время для теста.

`scripts/test-refresh-session-inventory.sh` создаёт временные пустые файлы
`.jsonl` и проверяет число, ID, размер и дату в индексе. Тест не содержит и не
открывает текст транскриптов.

`ai/skills/session-audit/SKILL.md` хранит прикладной сценарий. Он загружается
только для аудита и не добавляет постоянный контекст обычным задачам.
`ai/architecture.md` хранит краткий обзор, а `ai/decisions.md` — постоянные
границы автоматизации.

## Запуск

Плановая отдельная задача раз в три дня запускает только обновление inventory
и предлагает показать его. После выбора пользователем точных ID агент может
прочитать только их, применить методику и немедленно добавить безопасный
результат в журнал. Для следующих ID требуется новое явное указание.

При отсутствии папки транскриптов, ошибке генерации или неизвестном ID аудит
останавливается, а журнал не меняется.

## Совместимость и архив

Содержимое `hub-session-audit` не удаляется и не редактируется. В перенесённом
журнале сохраняется ссылка на старый снимок и маркировка `архивный`; новые
запуски используют только `session-inventory.md`.

## Проверка

1. Тест скрипта проходит в изолированной временной папке.
2. Генерируемый индекс не содержит текста транскриптов.
3. Инструкция не разрешает чтение без точных ID и не разрешает автоматические
   изменения архитектуры.
4. Проверка согласованности шаблона проходит после изменения канонических
   списков, если такие списки затронуты.
