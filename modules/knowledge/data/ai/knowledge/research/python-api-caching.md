# Кэширование запросов на Python: локальная память и общее хранилище

## Statement

Конспект предоставленной пользователем статьи. Ниже переданы утверждения источника; они не являются принятым решением проекта или независимой проверкой документации библиотек.

Кэш сохраняет результат дорогой операции для повторного использования. Польза зависит от стоимости проверки кэша, числа повторных запросов и допустимой устарелости данных. Кэширование не устраняет причину медленной исходной операции.

### Выбор механизма

| Задача | Механизм из статьи | Ограничения |
| --- | --- | --- |
| Повторные вычисления без срока жизни результата | functools.lru_cache | Память одного процесса; аргументы должны быть хешируемыми; встроенного срока жизни нет |
| Локальные данные со сроком жизни | cachetools.TTLCache | Память одного процесса; общий доступ из потоков требует синхронизации |
| Общий кэш для нескольких процессов или серверов | Redis или другое внешнее хранилище | Сетевые обращения, преобразование данных и отдельная инфраструктура |

- Ограничение размера lru_cache задаёт число записей. При переполнении вытесняется давно не использовавшаяся запись. Изменяемые возвращаемые объекты нельзя бездумно менять: повторный вызов получает сохранённый объект.
- Потокобезопасность внутренней структуры lru_cache не предотвращает повторное вычисление при одновременном промахе. cachetools требует отдельной синхронизации при доступе из нескольких потоков.
- Истёкшая запись TTLCache перестаёт быть доступной, но её физическое удаление может происходить позже.
- У каждого процесса свой локальный кэш и свой прогрев. Несколько процессов не означают автоматически фиксированное падение доли попаданий.

### Чтение и обновление общего кэша

Описанная схема: сформировать ключ, проверить кэш, при промахе получить данные из источника, сохранить их со сроком жизни и вернуть результат. Пример Redis записывает значение и срок жизни одной командой. Приложение отвечает за преобразование данных; статья использует JSON и предупреждает об опасности загрузки pickle из недоверенных источников.

Для изменяемых данных статья сочетает срок жизни и явное удаление записи после изменения источника. Эта схема сама по себе не обеспечивает строгую согласованность: при конкурентных чтениях и записи возможны гонки.

### Одновременные промахи и отказ кэша

- Случайный разброс срока жизни снижает вероятность одновременного истечения множества ключей. Он не защищает один популярный ключ от повторных запросов к источнику.
- Объединение одновременных запросов к одному ключу действует только в своей области координации. Локальный механизм защищает один процесс; нескольким процессам нужна общая координация.
- Другие описанные варианты: заранее обновлять данные в фоне или временно отдавать старые данные во время обновления, когда требования это допускают.
- При отказе Redis прямое обращение к источнику требует тайм-аутов и ограничения нагрузки. Иначе отказ кэша может перегрузить источник.
- Срок жизни выбирают по допустимой устарелости данных, нагрузке на источник и измерениям. Несколько уровней кэша допустимы, но не обязательны.
