# Полная синхронизация Хаба

Используй этот навык только для явного запроса на полную синхронизацию, например: «Полная синхронизация Хаба». Вопрос о состоянии, ходе или результате сам по себе ничего не меняет.

## Обязательные правила

- Прочитай действующий `ai/architecture.md`, `ai/modules.md` и относящиеся к действию правила Хаба. Не копируй и не отменяй общие правила.
- Каждый запуск заново читай реестр и актуальный индекс проектов. Обрабатывай все активные зарегистрированные проекты, в том числе созданные после прошлого запуска. Архивы пропускай, пока пользователь прямо не включит их.
- До чтения каждого проекта выполни `bash scripts/check-hub-registry.sh <hub> --project <id>`. Если проверка завершилась ошибкой или недоступна, не читай и не меняй проект. Сверяй канонический путь проекта и каждого изменяемого пути с разрешённым корнем; не следуй символическим ссылкам за его пределы.
- Канонические файлы задач меняй только через `python3 scripts/task_records.py write` с проверенными параметрами. Сверяй спорные статусы задач с текущим источником «Напоминаний», если он доступен; сама синхронизация не доказывает выполнение.
- Не раскрывай секреты. Проверь точные изменения и историю отправляемых коммитов на ключи, токены, пароли, персональные и медицинские данные. Не пересказывай найденный секрет в отчёте.
- Не используй `git add -A`, принудительную отправку, очистку чужих изменений, небезопасное переключение ветки, обход проверок или `--allow-dirty`.
- Перед любой отправкой проверь видимость хранилища. В открытое хранилище отправляй только после проверки всех новых коммитов и точных файлов на личные, медицинские, ветеринарные данные и секреты; при сомнении остановись.

## Порядок работы

1. Обнови список активных проектов из реестра. Для каждого проекта отдельно проверь регистрацию, рабочую папку, текущую ветку, `git status`, локальные коммиты, расхождение с удалённой веткой и все удалённые адреса. Если дерево было грязным до начала этой синхронизации, не включай чужие или неразобранные изменения; отдели точные разрешённые пути, а если это невозможно — останови проект.
2. Убедись, что удалённый адрес соответствует этому проекту. Через подключённый сервис проверь видимость хранилища. Для личных, медицинских и ветеринарных материалов используй только закрытое хранилище. Не меняй видимость существующего хранилища.
3. Если удалённого адреса нет, проверь список доступных хранилищ и поиск по точному и похожему имени. Создавай новое закрытое хранилище и добавляй удалённый адрес только при прямом разрешении пользователя в текущей задаче. Не перезаписывай другой адрес, не используй архивное хранилище и не создавай открытое хранилище.
4. Проверь весь точный набор изменений и каждый локальный коммит впереди удалённой ветки. Отделяй подтверждённые факты от гипотез. Останови проект, если обнаружил секрет, сомнительное содержимое, неподтверждённый статус задачи или неясное удаление. Продолжай независимые проекты.
5. Для кода запусти относящиеся к нему проверки. Новые тесты подтверждай мутацией каждого теста. Для изменений второго и третьего уровней получи независимую приёмку точного результата до отправки.
6. Зафиксируй только проверенные пути явной командой `git add -- <пути>`. Сделай отдельное сохранение по проекту, чтобы результат было легко проверить и возобновить.
7. Перед отправкой повторно проверь закрытую видимость хранилища, назначение ветки и точный список коммитов. Отправляй только обычным fast-forward. При конфликте, расхождении веток или наличии чужих изменений остановись для этого проекта.
8. После ошибки отправки сначала сравни локальный коммит с удалённой веткой через `git ls-remote` или подключённый сервис. Пока результат не установлен, не повторяй отправку. Отметь фактически успешные проекты как завершённые; не сообщай общий успех при частичном результате.
9. Для обновления Хаба используй штатный `scripts/update-installed-hub.sh`: сначала предварительный просмотр, затем сверка плана и источника, потом применение. Если защита останавливает обновление из-за несохранённых изменений или конфликта, не обходи её и не заменяй файлы; сообщи, что именно остановлено, и запроси решение о сохранении изменений.
10. Проверь установленные контрольные суммы, `ai/modules.md`, состояние локальных и удалённых веток. Составь отчёт по каждому проекту отдельно.

## Возобновление и отчёт

Сначала сверяй фактические ветки, коммиты и состояние установленного Хаба; не полагайся на старый список или сообщение о незавершённом этапе. Повторяй только подтверждённо неуспешный этап. Если ведёшь техническую запись продолжения, храни только идентификаторы проектов и коммитов, контрольные суммы, время и результат этапа; не сохраняй тексты файлов, секреты или медицинские сведения.

Для каждого проекта укажи: проверка; сохранение; отправка и закрытое хранилище; установка, если относится; причина остановки и безопасный следующий шаг. Отдельно укажи проекты без изменений и частичные ошибки.

Пример явной команды: «Полная синхронизация Хаба».
