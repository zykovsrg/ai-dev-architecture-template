# Новый проект в «Напоминаниях»

Только для нового проекта текущего запроса, если `planning` указан в `ai/modules.md` и в `ai/reminders-sync.json` стоит `enabled: true`.
Новый проект получает отдельный список. Его задачи обычные, без искусственного
напоминания с названием проекта. Старые привязки с родителем сохраняют свой режим.
Обычный `sync` / `publish` работает только с уже связанной конфигурацией;
команду `ensure-project` не выдумывайте.

## Подготовка без внешней записи

1. Прочитайте `ai/reminders-sync.json`, указанные файлы разрешений, метаданные
   выбранной группы и карточку только нового проекта. Подтвердите регистрацию,
   выбранную группу и отсутствие незавершённых операций. Не меняйте старые
   привязки или базу других проектов. Используйте доверенный `binary` конфигурации.
2. Получите свежие `list_lists`. Требуется `guarded_list_creation: true` и
   достоверный `account_id` существующей группы. Выберите существующую нативную
   группу по верхнему активному предку выбранной группы Хаба через
   `structure.native_groups`. Например, каноническая подгруппа остаётся прежней,
   а её отдельный список отображается в верхней группе приложения. Не создавайте
   и не перестраивайте группы. Неоднозначность, отсутствующая карта или сведения
   об учётной записи останавливают внешнюю часть.
3. Покажите точный ID и имя проекта, имя нового списка, UUID группы и учётной
   записи, единственное добавление разрешения и будущие поля привязки. Никакого
   `create_reminder` с темой проекта в этом плане нет. Пустой проект не требует
   придуманной первой задачи. Совпадающее имя существующего списка не позволяет
   присвоить его по названию: остановитесь до точного решения пользователя.
4. Сохраните исходные суммы конфигурации и разрешений, подготовьте резервную
   копию и журнал создания в служебной области Хаба. Проведите независимую
   приёмку точного плана перед внешним действием. Запрос создания разрешает
   необходимые шаги в своей области, но не отменяет явных ограничений пользователя
   на расширение доступа. Когда отдельное согласие требуется, получите его
   на точное добавление до применения.

## Разрешение только нового списка

Исходный `allowlist_file` не изменять: его байты могут закреплять старые отмены.
Обычные операции используют `standard_allowlist_file` по фиксированному пути
`<hub>/ai/reminders-standard-allowlist.json`. Не добавляйте имена напрямую.

Выполните существующую команду:

```text
python3 scripts/reminders_project_lists.py permission-preview --hub <hub> --list-name <точное-имя>
```

Проверьте, что план только добавляет одно имя и сохраняет прежние разрешения.
Примените именно этот проверенный план командой `permission-apply --plan <путь>
--sha256 <сумма-плана> --approve`. Флаг фиксирует уже имеющееся согласие, не создаёт
его. Перечитайте файл и завершённую квитанцию. Этот шаг не меняет конфигурацию.
Для следующих нативных операций используйте временную копию конфигурации
с `standard_allowlist_file`; постоянную связь запишите только после подтверждения списка.

## Создание списка и привязки

Используйте обычный `reminders_sync.Native` и доступные проверенные операции.
Не меняйте исполнитель ради обхода отказа и не открывайте дополнительные команды.
Перед каждым действием повторно проверьте ожидаемые суммы и метаданные.

1. Сохраните намерение в журнале ДО `manage_list`:
   `action: create`, `list: <имя>`, `expected_account_id: <UUID учётной записи>`.
   Нативная проверка должна отказать до создания, если текущая учётная запись
   не совпадает. Сразу сохраните полученный UUID; перечитайте `list_lists`,
   подтвердите имя, UUID, учётную запись и отсутствие чужого содержимого.
2. Запишите намерение перед `manage_list` с `action: update`,
   `list: <новый UUID>`, `group: <UUID группы>`,
   `expected_group_id: <свежее значение или null>`. Если свежий снимок уже показывает
   нужную группу, действие не повторяйте. Перечитайте UUID, имя, группу и учётную запись.
3. Не создавайте родителя через `create_reminder`. После проверок сохраните
   конфигурацию сравнением с ожидаемыми исходными байтами. Новая запись содержит:

```json
{
  "layout": "project_list",
  "list_id": "<новый UUID>",
  "list_name": "<имя проекта>",
  "parent_id": null,
  "native_group_id": "<UUID группы приложения>",
  "account_id": "<UUID учётной записи>",
  "tasks": {},
  "history": {}
}
```

   Одновременно установите постоянный `standard_allowlist_file`, добавьте ровно
   `structure.list_roles[<list UUID>] = {kind: project, project_id: <ID>}` и
   `structure.projects[<ID>] = {group: <выбранная каноническая группа Хаба>, list_id: <UUID>}`.
   Даже при показе в верхней группе приложения исходную группу Хаба не переписывать.
   Существующие роли, базу и связи оставить прежними; пересев не запускать.
4. Перечитайте конфигурацию и список. Выполните просмотр
   `python3 scripts/reminders_sync.py sync --hub <hub> --project <ID>`.
   Применяйте только проверенные изменения запрошенных задач с повторным чтением.
   У пустого проекта нет корневого напоминания и нет вымышленных задач.

При неизвестном результате создания или назначения группы остановитесь с журналом
и частичным результатом; не повторяйте создание и не выбирайте объект по имени.
Не удаляйте список как автоматический откат. Сообщите, что создано и какая проверка
осталась. Установка инструкции не является доказательством реального создания:
при фактическом запросе нужны нативное чтение и независимая приёмка результата.
