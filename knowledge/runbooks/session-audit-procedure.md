# Процедура разбора сессии хаба

## Statement

Как разбирать один транскрипт сессии `_ai-hub`, чтобы оценить работу
архитектуры, а не содержание рабочей задачи.

До чтения пользователь указывает точные ID в одном сообщении. Это разрешает
читать только эти ID в текущем запуске и сразу добавить их безопасные результаты
в журнал. Задачи, правила и настройки при этом не меняются.

## Evidence

### Где лежат транскрипты

Актуальный безопасный список файлов, их размеров и дат находится в
`knowledge/research/session-inventory.md`. Он обновляется без чтения
содержимого транскриптов. Имя файла не равно интерфейсному `sessionId`;
сопоставление с проектом требует первой реплики внутри уже подтверждённого файла.

### Что проверять

1. Идентификация: файл, размер, даты и зарегистрированный проект диалога.
2. Роутинг: `Project`/`Path`, явное подтверждение и отсутствие чтения до него.
3. Заголовок работы: `Project`/`Mode` и смена `Mode`.
4. Скиллы: вызовы, завершённость и брошенные процедуры.
5. Память: обновление `current-task`, `future-tasks`, `changelog`, `decisions`.
6. Трения: существенные поправки пользователя к цели, границам или результату.
7. Незакрытые хвосты, которых нет в памяти задач.
8. Обход границ: чужие пути, неверный проект, protected write без режима.
9. Эффективность: сопоставить задачу, первое действие, существенные поправки и итог.

Для пункта 9 указывается ровно один status: `точно`, `нужна корректировка` или
`недостаточно данных`. Обычное предпочтение, нейтральный вопрос и новая задача
не считаются корректировкой.

### Формат результата

Не более 40 строк на сессию. Для каждого пункта — безопасное свидетельство или
`не найдено`. Для эффективности — status и безопасное evidence: ID и ссылка на
сообщение либо обезличенная выжимка.

Не сохранять секреты, ключи, сырые значения окружения, личные и клиентские
данные даже цитатой. Вместо значения писать `<секрет опущен>` или `<опущено>`.

## Scope

Только транскрипты хаба `_ai-hub`. Это проверка соблюдения архитектурных
процедур, а не содержательная оценка рабочих задач.

## Related records

- `knowledge/research/checked-sessions.md` — журнал разобранных сессий.
- `knowledge/research/session-inventory.md` — автоматически обновляемый список metadata.
